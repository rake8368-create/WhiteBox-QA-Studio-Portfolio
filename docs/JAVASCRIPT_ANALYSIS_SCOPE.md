# JavaScript 분석 범위

Day 07의 JavaScript 분석기는 `.js`, `.mjs`, `.cjs`, 표준 `.jsx`를 읽고 `AnalysisCapabilities.StaticRules`를 제공합니다. 확장자는 대소문자를 구분하지 않습니다. TypeScript 계열(`.ts`, `.tsx`, `.mts`, `.cts`)은 확장자만 식별합니다.

## 정적 규칙

| 규칙 | 위험도 | 판단 기준 |
| --- | --- | --- |
| JS-001 | 높음 | Tree-sitter의 `ERROR`와 `MISSING` 노드를 보고하고 파일 내 같은 시작 위치는 한 번만 표시합니다. 줄과 열은 원본의 1부터 시작하는 UTF-16 위치입니다. 탭은 한 코드 단위, 이모지 서로게이트 쌍은 두 코드 단위로 집계합니다. 오류 위치는 파서의 구문 복구 결과이며 지원 범위 밖 문법에서도 진단될 수 있습니다. |
| JS-002 | 낮음 | `catch {}`와 `catch (error) {}`를 검토합니다. 주석, 빈 문장, 빈 중첩 블록은 본문의 실행문으로 세지 않습니다. 기록, 복구 호출, 선언, `return`, `throw` 등 본문에 문장이 있으면 보고하지 않습니다. 각 catch의 본문을 독립적으로 평가하며 `finally`의 문장은 별도입니다. 예외를 의도적으로 무시했을 수 있습니다. |

구문 오류가 있는 파일에서는 JS-001을 적용하고 JS-002 생략 사유를 **분석 참고**에 남깁니다. 해당 파일에서 구문 트리를 얻었다면 분석 수에 포함합니다. 초기화·파싱 실패 또는 트리 생성 실패는 해당 파일의 사유를 남기고 다른 파일과 언어를 계속 분석합니다.

## 입력과 제한

- 로컬 파일·폴더와 공개 HTTPS Git 기본 브랜치 HEAD를 가져옵니다. JavaScript의 발견 수와 분석 수는 **분석 참고**에서 확인할 수 있습니다. 로컬은 UTF-8과 BOM이 있는 유니코드를 지원합니다. Git 객체에는 엄격한 UTF-8과 BOM 유니코드 읽기 정책을 적용합니다.
- 폴더와 Git의 자동 탐색은 정확히 `node_modules`인 경로 구간을 대소문자 구분 없이 제외합니다. 하위 항목은 언어와 관계없이 발견 수나 소스 읽기 한도에 포함되지 않습니다. `node_modules` 아래를 직접 폴더로 선택한 경우에도 자동 탐색에서 제외합니다. 사용자가 개별 선택한 파일에는 기존 읽기 정책을 적용합니다. `dist`, `build`, `vendor`에는 별도 제외 규칙을 추가하지 않았습니다.
- 로컬과 Git 소스 가져오기 한도는 **2,000개**, 파일당 **2 MiB**, 전체 **32 MiB**입니다. 직접 JavaScript 분석 입력 한도는 파일당 **2 Mi UTF-16 코드 단위**, 분석당 **32 Mi UTF-16 코드 단위**입니다.
- 구문 진단은 파일당 **100개**, 분석당 **2,000개**입니다. 정적 규칙 진단은 파일당 **500개**, 분석당 **5,000개**입니다. 입력이나 진단을 실제로 생략한 경우 **분석 참고**에 이유를 표시합니다.
- 입력·진단 한도는 네이티브 파싱의 실행 시간과 메모리 사용에 하드 상한을 제공하지 않습니다.

## 파서 및 결과 호환성

Windows x64 단일 EXE는 TreeSitter.DotNet 1.3.0 런타임과 JavaScript grammar를 사용합니다. JavaScript와 JSX 소스는 데이터로만 읽습니다. Node.js, npm, 프로젝트 스크립트, 대상 코드 실행과 의존성 설치는 사용하지 않습니다. [서드파티 고지](THIRD_PARTY_NOTICES.txt)

ESM, CommonJS, 표준 JSX의 구문을 파싱합니다. 컴파일러 수준의 검증, ECMAScript 조기 오류, Node.js 모듈 해석 및 적합성, 의미 분석, 타입 추론, CFG, 복잡도, 호출 그래프는 지원 범위 밖입니다. WPF, JSON v1, Excel 네 시트는 같은 규칙 ID, 위험도, 파일과 위치를 사용합니다. [공개 검증 보고서](VERIFICATION.md)
