# Java 분석 범위

Day 06은 파일 선택, 폴더와 공개 HTTPS Git HEAD의 `.java` 파일을 읽습니다. 기존 파일 수·용량 제한과 링크·LFS 처리, Git 취소·시간 초과 정책을 적용합니다. UTF-8과 BOM이 있는 유니코드 인코딩을 지원합니다. 발견 수와 분석 수는 분석 참고에서 확인할 수 있습니다.

| 규칙 | 위험도 | 판단 근거 |
| --- | --- | --- |
| JAVA-001 | 높음 | Tree-sitter의 `ERROR` 및 `MISSING` 노드를 시작 위치에 표시합니다. 중첩된 복구 노드도 위치가 다르면 표시하고, 동일 위치는 트리 순회에서 처음 만난 진단 한 건으로 합칩니다. 구문 오류가 있는 파일은 구문 진단만 수행하고, 나머지 파일의 분석은 이어집니다. |
| JAVA-002 | 낮음 | `catch` 본문이 비어 있거나 주석, 빈 문장, 빈 중첩 블록만 있을 때 표시합니다. 복구 호출, 재던지기, 지역 변수·타입 선언, 조건문이나 라벨이 붙은 문장이 있으면 빈 본문으로 보지 않습니다. |
| JAVA-003 | 보통 | `catch`의 타입 목록에서 단순 이름 `Throwable`과 한정 이름 `java.lang.Throwable`을 찾아 각각의 근거와 주의 문구를 표시합니다. 한정 이름은 각 이름 요소를 비교하므로 주석이나 어노테이션이 사이에 있어도 찾습니다. `Exception`과 `custom.Throwable` 등 다른 타입 표기는 대상에서 제외합니다. 다중 catch당 한 건을 표시하며 두 표기가 함께 있으면 한정 이름을 근거로 사용합니다. |

위치 표시는 접두사에 한글, 이모지, 탭이 있는 경우에도 원본의 줄을 가리킵니다. 행과 열은 1부터 시작하며 열은 편집기와 같은 UTF-16 코드 단위를 사용합니다. CRLF와 CR은 파서 입력에서 LF로 정규화하므로 원본 줄 순서는 유지됩니다.

구문 진단은 파일당 100개, 한 분석에서 Java 전체 2,000개까지 표시합니다. 추가 진단을 생략한 파일은 분석 참고에 사유를 남기며 결과는 부분 성공으로 표시됩니다. 이 한도는 파싱 후 보관할 진단 건수에 적용됩니다. 가져오기 한도는 파일 2,000개, 파일당 2 MiB, 전체 32 MiB입니다. 파일마다 새 파서를 사용하며 초기화 또는 파싱에 실패하면 해당 파일의 사유를 표시합니다.

JAVA-003은 이름을 검토하도록 안내합니다. 단순 이름은 같은 이름의 사용자 타입으로 해석될 수 있습니다. 한정 이름도 문법상 표기만 확인하므로 실제 타입 바인딩과 다중 catch의 유효성은 컴파일러로 확인해야 합니다.

Java 기능은 구문과 정적 규칙입니다. 타입·스코프·의존성 해석, Java 버전별 컴파일 검증, 호출 그래프, CFG와 복잡도는 범위 밖입니다. 앱은 대상 코드를 구문 트리로만 읽습니다. 이상을 확인한 파일과 줄은 WPF에서 이동할 수 있고 JSON v1 이력과 Excel 상세 결과에 저장됩니다. Excel의 네 번째 시트에는 C#과 Python의 CFG가 기록됩니다.

Windows x64 단일 EXE는 기존 `TreeSitter.DotNet 1.3.0`의 런타임과 Python, Java, JavaScript, C++, TypeScript, TSX 문법을 포함합니다. Java 네이티브 DLL은 `tree-sitter-java.dll`이며 export는 `tree_sitter_java`입니다. 패키지의 Java 문법 소스는 `e10607b4`를 기준으로 하며 MIT 라이선스 고지를 배포본에 포함합니다. ## Day 06 추가 3차 · 직접 입력과 결과 건수 보호

- Java 분석기를 직접 호출한 입력도 파일당 최대 **2,097,152 UTF-16 코드 단위**, 한 번의 Java 분석 호출에서 합계 **33,554,432 코드 단위**까지 허용합니다. 가져오기에서 기존에 적용하는 **원본 바이트 기준** 2 MiB/32 MiB 한도는 그대로입니다. 경계를 넘은 Java 파일은 분석에서 제외하고 사유를 표시하되 나머지 Java/C#/Python 파일은 계속 처리합니다.
- 정상 구문 Java 파일에 대해 JAVA-002·003을 포함한 정적 규칙 결과는 파일당 **500건**, 분석당 **5,000건**까지 보관합니다. 실제 추가 결과가 발생하는 경우에만 해당 파일에 생략 안내를 추가합니다. 기존 JAVA-001 구문 오류 제한(파일당 100건, 분석당 2,000건)은 독립적으로 유지합니다.
- 이 한도들은 파서에 **전달하기 전 입력 문자 수**와 **파싱 이후 저장할 진단 건수**만 관리합니다. Tree-sitter 네이티브 파싱의 시간·메모리를 강제로 중단하거나 절대적인 상한을 보장하지 않습니다. 시간 제한이나 프로세스 격리는 향후 설계 과제입니다.
