# 제어 흐름 분석 설계

## 현재 구현 범위 · v0.2.1-dev

C# 파일의 구문 트리를 기존 WB-001~003 분석과 공유합니다. 입력 묶음의 `CSharpCompilation`에 기본 .NET 메타데이터를 연결하고, 각 구문 트리의 `SemanticModel.GetOperation`으로 메서드의 `IMethodBodyOperation`을 얻습니다. `ControlFlowGraph.Create`의 시작·종료·기본 블록, 도달 가능 여부, 참·거짓 연결과 구문 위치를 표시합니다. 단일 EXE에서는 로드된 기본 프레임워크 어셈블리의 메타데이터로 같은 참조를 만듭니다. [Roslyn ControlFlowGraph](https://learn.microsoft.com/en-us/dotnet/api/microsoft.codeanalysis.flowanalysis.controlflowgraph) · [Roslyn BasicBlock](https://learn.microsoft.com/en-us/dotnet/api/microsoft.codeanalysis.flowanalysis.basicblock)

메서드 단위는 일반 C# 메서드 선언입니다. 생성자, 속성 접근자, 람다, 지역 함수, 최상위 문장은 복잡도 표의 독립 항목으로 생성하지 않습니다. 같은 프로젝트나 프로젝트 없는 묶음에서 파일 간 사용자 정의 타입을 해석할 수 있습니다. 앱은 프로젝트의 직접 선언에서 정적 컴파일 기호와 언어 버전을 읽으며, 로컬 범위 안의 명시적 DLL 참조는 메타데이터로만 연결합니다. 메서드 본문 없음, 구문·의미 오류, 그래프 생성 실패에는 사유와 **분석 불가**를 표시하고 점수는 비워 둡니다.

WB-002는 필터 또는 catch 진입에서 각 `throw ex;`까지 CFG를 따라가며 해당 catch의 예외 변수 심볼에 대한 재대입 상태를 합칩니다. 참으로 끝난 필터 경로만 catch 본문에 연결합니다. 도달하지 않는 쓰기는 제외하며, 호출이나 암시적 예외 전이의 효과를 확정할 수 없는 경로는 검토 필요로 표시합니다. 이 판정은 CFG의 경로를 따르므로 서로 다른 지점의 조건식 사이의 논리적 상관관계까지 증명하지 않습니다.

## 기초 복잡도(MVP) 계산

기본값 1에 Roslyn이 도달 가능하다고 표시한 지원 조건 블록 수를 더합니다. 조건 값과 참·거짓 목적지가 있는 블록을 한 번만 더합니다. Roslyn이 도달 불가로 표시하는 분기 블록은 분기 목록에 둘 수 있으며 점수 집계에서 제외합니다.

| 구문 | 집계 기준 |
| --- | --- |
| 직선 코드 | 1 |
| `if/else`, 중첩 `if` | 조건 블록마다 1을 추가. `else` 자체는 0 |
| 종료 조건이 있는 `for`, `while`, `do/while` | 반복 여부를 결정하는 조건 블록마다 1을 추가 |
| 일반 `foreach` | Roslyn이 만든 암시적 `MoveNext` 조건 블록에 1을 추가. 루프 본문에 있는 명시적 호출은 해당 조건의 줄에 표시하고 암시적 자원 정리 조건은 제외 |
| 상수 `case`를 사용한 `switch` 문 | CFG의 도달 가능한 항목 비교 블록마다 1을 추가. `default` 자체는 0 |
| `&&`, `||`, `?:` | CFG가 생성한 도달 가능한 단락 평가·삼항 조건 블록을 각각 집계 |

예외 처리 전이·필터, 패턴 기반 `switch`, 특수 `foreach`, null 조건부 접근·병합, `goto`·`yield`, 비동기 상태 전이와 기타 미분류 조건이 있는 메서드는 제한 사유를 표시합니다. 예외 처리 블록 안의 일반 `if`처럼 지원되는 조건은 집계합니다. 복잡도 평가의 기본 상한 5·10·20은 `ComplexityBands`로 분리되어 있으며 현재 UI는 기본값을 사용합니다.

## 화면과 데이터

- 기존 규칙 결과와 별개 탭에서 메서드의 파일, 시작·종료 줄, 점수·평가·상태를 표시합니다. 선택한 분기의 줄과 참·거짓 대상 블록을 보며, 현재 입력에서는 줄 선택 시 편집기로 이동합니다.
- Excel 네 번째 시트에 메서드별 집계를 기록합니다. 이전 시트의 위험도 집계는 기존 규칙 결과를 사용합니다.
- 스키마 버전 1 JSON의 선택적 `controlFlow`에 메서드, 기본 블록, 분기와 짧은 조건 발췌를 기록합니다. 기존 필드만 있는 이력을 열면 **이 분석 이력에는 제어 흐름 결과가 없습니다.**를 표시합니다. 보관 이력의 소스는 앱에서 재구성하지 않습니다.
- 점수와 도달 가능 여부는 정적 구조의 정보입니다. 실제로 지난 실행 경로, 실행 성공 여부와 커버리지는 대상 테스트를 실행해 수집해야 합니다. 현재 화면과 Excel은 **테스트 커버리지 미측정**을 표시합니다.

## 후속 분석

프로젝트 간 참조 모델, 접근자·지역 함수의 복잡도, WB-002에서 호출과 암시적 예외 전이에 걸친 재대입 판정을 더 검증합니다. 대상 테스트의 분기 실행 기록은 동일 소스 버전과 위치가 확인된 경우에만 연결합니다.
