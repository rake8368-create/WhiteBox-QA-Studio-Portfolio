# TypeScript·TSX 정적 분석 범위

TypeScript는 `.ts`, `.mts`, `.cts`를, TSX는 `.tsx`를 대소문자와 관계없이 분석합니다. 로컬 파일·폴더와 공개 HTTPS Git HEAD에서 소스를 읽을 수 있습니다. 기존 TreeSitter.DotNet 1.3.0의 두 grammar를 사용합니다. [분석 아키텍처](ARCHITECTURE.md)

| 규칙 | 위험도 | 검토 범위 |
| --- | --- | --- |
| TS-001 | 높음 | Tree-sitter의 구문 복구 오류와 누락 토큰을 표시합니다. 같은 시작 위치의 중복을 제거하며, 좌표는 원본의 1부터 시작하는 UTF-16 줄·열입니다. |
| TS-002 | 낮음 | 바인딩 유무와 관계없이 빈 catch를 표시합니다. 주석, 세미콜론, 빈 중첩 블록만 있는 경우를 포함합니다. 선언·호출·실행문이 있으면 제외하고, 구문 오류 파일은 생략 사유를 표시합니다. 예외를 의도적으로 무시하는 경우가 있습니다. |

Tree-sitter의 복구 결과이므로 닫기 태그의 `>` 누락을 진단할 수 있고, 여는 태그와 닫는 태그의 이름 불일치는 놓칠 수 있습니다. 타입 검사와 추론, tsconfig·모듈 해석, 컴파일러·런타임의 모듈 규칙, CFG·복잡도와 의미 분석은 지원 범위 밖입니다. 가져온 소스는 텍스트로 분석하며 분석 대상, Node.js, npm 또는 tsc를 실행하는 과정은 없습니다.

직접 입력은 파일당 2 Mi·배치당 32 Mi UTF-16 코드 단위입니다. TS-001은 파일당 100건·배치당 2,000건, TS-002는 500건·5,000건까지 보고합니다. 가져오기 한도는 2,000개, 파일당 2 MiB, 총 32 MiB입니다. 폴더와 Git 자동 탐색에서는 `node_modules`를 제외합니다. 생략 사유는 **분석 참고**에 표시합니다. 이 한도는 네이티브 파싱 시간·메모리의 하드 상한을 보장하지 않습니다.

WPF에서 규칙 ID 검색, 위험도 필터, 현재 소스 줄 이동을 사용할 수 있습니다. Excel은 기존 네 시트에 TS 규칙과 범위를 표시합니다. JSON v1은 기존 필드에 결과와 집계를 저장하며, 이전 확장자 식별 전용 이력은 저장 당시의 발견·분석 수로 표시합니다.
