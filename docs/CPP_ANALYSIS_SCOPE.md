# C++ 정적 분석 범위

Tree-sitter.DotNet 1.3.0과 C++ grammar로 로컬 개별 파일·폴더 및 공개 HTTPS Git HEAD의 C++ 소스를 분석합니다. 대소문자 구분 없이 `.cpp`, `.cc`, `.cxx`, `.hpp`, `.hh`, `.hxx`를 읽습니다. `.h`는 미식별이고 `.c`는 확장자 식별 전용입니다.

## 정적 규칙

| 규칙 | 위험도 | 판단과 검토 방법 |
| --- | --- | --- |
| CPP-001 | 높음 | Tree-sitter의 구문 복구에서 나온 `ERROR`와 누락 토큰을 시작 위치별로 보고합니다. 원본 1부터 시작하는 UTF-16 줄·열을 사용합니다. 표시된 줄과 앞줄의 괄호, 구분 기호, 선언, 전처리 지시문을 확인합니다. |
| CPP-002 | 낮음 | `catch (...)`와 타입 지정 catch의 본문에서 실행문이나 선언이 없으면 보고합니다. 주석, 세미콜론, 빈 중첩 블록은 빈 본문으로 봅니다. 자식 토큰과 노드로 빈 문장과 호출을 구분하며, 중첩 catch는 각각 검사합니다. 의도적으로 예외를 무시하는 코드라면 무시 조건을 검토합니다. |

구문 복구 진단은 비활성 전처리 분기, 매크로에 의존하는 구문 또는 grammar가 지원하지 않는 문법에서도 생길 수 있습니다. 구문 오류 파일의 CPP-002와 조건부 분기에 속하거나 본문에 전처리 지시문이 있는 catch의 CPP-002는 생략 사유를 **분석 참고**에 표시합니다.

## 가져오기와 분석 한도

| 제한 | 파일당 | 분석당 |
| --- | ---: | ---: |
| 가져오기 바이트 | 2 MiB | 32 MiB |
| 직접 분석 UTF-16 코드 단위 | 2 Mi | 32 Mi |
| CPP-001 진단 | 100건 | 2,000건 |
| CPP-002 진단 | 500건 | 5,000건 |

가져오기는 최대 2,000개 파일을 처리합니다. 로컬 폴더와 Git의 자동 탐색은 `node_modules`를 대소문자 구분 없이 건너뜁니다. 읽기·분석 실패나 한도로 대상이 생략되면 사유가 남고 다른 파일의 분석은 계속됩니다. 입력 한도는 네이티브 파싱 시간이나 메모리의 하드 상한을 보장하지 않습니다.

## 화면, 이력, 보고서

- **분석 참고**에서 C++ 발견·분석 수와 전처리기 관련 제한을 봅니다. 결과 표에서는 규칙 ID 검색과 위험도 필터를 적용하거나 현재 소스 줄로 이동할 수 있습니다.
- JSON v1은 기존 필드에 C++ 결과와 집계를 저장합니다. 확장자 식별 전용으로 저장된 이전 C++ 이력은 기록 당시 상태로 열립니다.
- Excel은 분석 요약, 상세 분석 결과, 분석 한계 및 참고사항, 제어 흐름 분석 네 시트를 유지합니다. C++ 발견은 요약과 상세 결과에, 분석 범위와 전처리기 제한은 참고사항에 기록합니다.

## 분석 범위 밖

매크로 확장, 활성 전처리 분기 선택, 헤더 탐색, 컴파일러 진단, C++ 표준 적합성 검증, 의미 분석, 타입 추론, 제어 흐름(CFG), 복잡도 및 메모리 누수 분석은 범위 밖입니다. 가져온 파일은 텍스트 데이터로 처리합니다. 대상 코드, 컴파일러, 빌드 스크립트, CMake와 Makefile 실행은 분석 범위 밖입니다.
